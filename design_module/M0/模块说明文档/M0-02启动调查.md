## 完整生成链

1. `start_mounted_radar.sh` 创建时间戳与 UUID 唯一运行目录，绝对路径导出 `AI4_VIEW_STATUS=<本轮>/spectator_view.txt`；`AI4_VIEW_PLUGIN` 指向 `catkin_ws/devel/lib/libai4_scene_view.so`。`run_dir:=` 同步传入 `mounted_radar.launch`。不复用旧目录；准备阶段不生成 GUI 凭证。
2. CMake 用 `src/scene_view.cpp` 构建 `ai4_scene_view` 共享库，并链接 Gazebo、Qt Widgets。默认入口检查构建产物存在。
3. `static_uav.launch` 通过 `native_gzclient.sh` 启动客户端；脚本等实际 Gazebo 模型（以及默认模式的实际雷达消息），随后 `exec gzclient --gui-client-plugin <绝对库路径>`。启动进程继承本轮环境，工作目录不决定凭证位置。
4. `GZ_REGISTER_GUI_PLUGIN` 创建 GUIPlugin，`Load` 注册 PreRender。窗口出现只说明客户端存在；必须等实际用户相机、场景、两个模型 visual，再应用旁观视角。改后额外要求场景、相机 Initialized，并在后续渲染回调回读位姿匹配，才原子写出凭证。
5. `start_sensor_clock.py` 先等待数据组件，再解除物理暂停；随后给实际时钟、双机运动、相机/点云更新、GUI 凭证和数据窗口显示计数共 120 秒启动预算。典型约 150 秒退出可由该预算耗尽触发：异常使 required 节点退出，roslaunch 关闭全组。这是**已确认的退出机制**，不是本轮已复现的历史触发原因。
6. 正常传感器数据与 GUI 就绪互相独立。默认 GUI 未就绪不会降级成通过；`gui:=false` 显式跳过 Gazebo GUI 验收，仍核查运动、相机和世界坐标雷达及数据窗口。

## 已修复的确定缺陷

- 原插件在尝试写文件前就设 `applied_=true`，写入失败无检查、无日志且永远不重试。现改为实际相机位姿回读后写临时文件，关闭流和 rename 均成功后才停止回调；失败明确报告目标路径并重试。未延长健康超时，未移除 required，未伪造就绪。
- 原健康检查只检查文件存在。现要求位姿验证凭证、本轮生成时间、仍存活且环境路径匹配本轮的 GUI 进程；旧文件和其他实例不能使 GUI 通过。
- 原 roslaunch 即使因 required 节点失败也可能返回零，外层会误记正常关闭。现将本轮 `startup_error.txt` 原因保留在 run.json，并确保失败返回非零；startup_health 同时标记 failed。

- `gui:=false` 首轮发现布局辅助脚本仍查找 Gazebo 窗口，遇到 X11 窗口树变化时报错。现由 launch 传入 GUI 开关，无 Gazebo GUI 时不启动该辅助脚本；默认 GUI 路径保持启用。此改动发生于两次核心 GUI 长测之后，单独针对无 GUI 模式复验。
