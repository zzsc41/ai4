# 雷达仿真配置（Gazebo Ray / Lidar 插件模拟毫米波雷达）

> 依据《无人机项目实施拆解文档》第二章节点图谱（`/radar_sim` 行）、第五章分工（仿真环境交付条件）、第八章第 4 条（传感器近似说明）整理。
> 本文档对应「仿真环境」分工的雷达部分，产出 `/radar/points`（`sensor_msgs/PointCloud2`），供 `/cluster` 消费。
> **项目要求**：使用 Gazebo 的 **Ray 插件** 或 **Lidar 插件** 模拟毫米波雷达。

---

## 一、目标与选型

| 项目 | 内容 |
|---|---|
| 要求 | 用 Gazebo Ray/Lidar 插件模拟毫米波雷达 |
| 选型 | **Ray 插件**（`gazebo_ros_ray_sensor`）——首选 |
| 备选 | Lidar 插件（`velodyne_simulator` / `gazebo_ros_gpu_laser`），见第八章 |
| 输出 | `/radar/points`（`sensor_msgs/PointCloud2`） |
| 噪声 | 逐波束高斯噪声（`<noise type="gaussian">`） |
| 技术栈 | ROS Noetic + Ubuntu 20.04 + Gazebo Classic 11 |

**为什么用 Ray 插件**：

1. Gazebo 内置，Noetic 原生支持，无需第三方依赖；
2. SDF 里 `<noise type="gaussian">` 即可给每个波束的距离加高斯噪声，直接满足「含高斯噪声」要求；
3. 插件直接发布 `PointCloud2`，与第二章 `/radar/points` 接口**无缝对接**，无需转换节点。

---

## 二、可行性说明（为何 Ray/Lidar 可近似毫米波雷达）

依据主文档**第八章第 4 条**：

> 仿真阶段用 Gazebo 3D Lidar 插件近似毫米波雷达，二者特性有差异——毫米波点云稀疏且可带多普勒测速，Lidar 点云密集无速度信息。仿真聚类/滤波参数不能直接外推到真机。

因此本方案是**经项目拍板接受的近似**：

| 特性 | 毫米波雷达 | Gazebo Ray/Lidar | 处理方式 |
|---|---|---|---|
| 点云密度 | 稀疏（几十点） | 稠密（上千点） | 降低采样数 / 提高 `eps` 近似（见第五章） |
| 多普勒测速 | 有 | 无 | 由 `/tracker` 卡尔曼滤波自估速度（`Track.msg.velocity`） |
| 距离精度 | 厘米级 | 可配高斯 stddev 模拟 | 调大 `stddev` 更接近雷达量级 |
| 角度噪声 | 有 | 逐波束距离噪声 | 可接受 |

## 三、传感器配置（URDF / SDF）

雷达在仿真中**地基固定于世界原点**（主文档第八章第 1 条），传感器向下/向空域扫描敌机模型。

### 3.1 链接定义（URDF）

```xml
<link name="radar_link">
  <visual>
    <geometry><cylinder length="0.1" radius="0.15"/></geometry>
    <material name="grey"><color rgba="0.5 0.5 0.5 1"/></material>
  </visual>
  <collision>
    <geometry><cylinder length="0.1" radius="0.15"/></geometry>
  </collision>
</link>
```

### 3.2 传感器与插件（URDF 内 `<gazebo>` 块）

```xml
<gazebo reference="radar_link">
  <sensor type="ray" name="radar_ray">
    <pose>0 0 0 0 0 0</pose>
    <visualize>true</visualize>
    <update_rate>20</update_rate>

    <ray>
      <!-- 水平扫描：360° 全向 -->
      <scan>
        <horizontal>
          <samples>360</samples>
          <resolution>1</resolution>
          <min_angle>-3.14159</min_angle>
          <max_angle>3.14159</max_angle>
        </horizontal>
        <!-- 垂直扫描：形成 3D 点云（近似雷达俯仰覆盖） -->
        <vertical>
          <samples>16</samples>
          <resolution>1</resolution>
          <min_angle>-0.2618</min_angle>
          <max_angle>0.2618</max_angle>
        </vertical>
      </scan>

      <range>
        <min>0.5</min>
        <max>100.0</max>
        <resolution>0.01</resolution>
      </range>

      <!-- 高斯噪声：逐波束独立采样，加到距离量测上 -->
      <noise>
        <type>gaussian</type>
        <mean>0.0</mean>
        <stddev>0.02</stddev>
      </noise>
    </ray>

    <!-- 关键：Ray 插件，直接输出 PointCloud2 -->
    <plugin name="radar_sim" filename="libgazebo_ros_ray_sensor.so">
      <ros>
        <namespace>/</namespace>
        <remapping>~/out:=/radar/points</remapping>
      </ros>
      <output_type>sensor_msgs/PointCloud2</output_type>
      <frame_name>radar_link</frame_name>
    </plugin>
  </sensor>
</gazebo>
```

> **说明**：插件实例名 `radar_sim` 即对应第二章图谱中的 `/radar_sim` 节点职责「Gazebo 3D Lidar 插件扫描敌机模型 + 高斯噪声」。使用内置插件后**无需再单独写 `/radar_sim` ROS 节点**——扫描、加噪、发布由插件承担。

## 四、参数说明与调优（向毫米波靠拢）

| 参数 | 位置 | 作用 | 调优建议 |
|---|---|---|---|
| `update_rate` | `<sensor>` | 出帧频率 | 10–20 Hz（与后端处理节拍匹配） |
| `horizontal/samples` | `<scan>` | 水平点数 | 360° 全向；**想要稀疏可降到 60–120** |
| `vertical/samples` | `<scan>` | 垂直线数 | 16 线出 3D 点云；**稀疏可降到 4–8** |
| `range/max` | `<range>` | 最大量程 | 按拦截距离设（如 100 m） |
| `range/resolution` | `<range>` | 距离分辨率 | 0.01 m |
| `noise/stddev` | `<noise>` | 高斯噪声标准差 | **0.01–0.05 m**；越大越接近雷达量级 |
| `output_type` | `<plugin>` | 输出消息类型 | 固定 `sensor_msgs/PointCloud2` |
| `frame_name` | `<plugin>` | 点云坐标系 | 与 `radar_link` 一致 |

> **模拟毫米波稀疏性**：毫米波点云远稀于 LiDAR。若希望仿真更贴近雷达，可**降低 `samples`**（如水平 120、垂直 8），并在 `/cluster` 用较大 `eps`；但主文档第八章第 4 条已声明「参数不能外推真机」，故此处以**跑通链路**为优先，稀疏化非强制。

## 五、与节点接口的对接

```
Gazebo Ray 插件 ──发布──▶ /radar/points (sensor_msgs/PointCloud2) ──订阅──▶ /cluster
```

| 上游 | 话题 | 消息类型 | 下游 |
|---|---|---|---|
| `radar_sim`（Ray 插件） | `/radar/points` | `sensor_msgs/PointCloud2` | `/cluster`（点迹聚类） |

- `/cluster` 的 `filter_ground` 直接吃 `PointCloud2`，转换为内部 `Point3D`（`x, y, z`，`intensity` 可留 0）后进 `dbscan_cluster`。
- 接口定义与《数据类型.md》第五章「外部标准 ROS 消息」一致，**不改动任何已有定义**。

## 六、启动与验证

### 6.1 启动

```bash
# 1. 加载含雷达的世界/模型
roslaunch <pkg> <radar_world>.launch

# 2. 确认话题存在
rostopic list | grep radar
# 预期输出：/radar/points
```

### 6.2 验证

```bash
# 查看点云帧率与坐标系
rostopic hz /radar/points
rostopic echo /radar/points/header -n1

# RViz 可视化：Fixed Frame = world，添加 PointCloud2 → /radar/points
rosrun rviz rviz
```

**验收判据**（对应第七章阶段 1「环境可跑通」）：

- `/radar/points` 稳定以设定频率发布；
- RViz 可见**敌机模型处**出现点云簇，且随敌机飞行脚本移动；
- 关闭噪声（`stddev=0`）对比，点云位置出现可见抖动，证明高斯噪声生效。

## 七、备选方案：Lidar 插件

若需要更「标准」的多线 LiDAR 行为或 GPU 加速，可替换为：

| 方案 | 插件 | 说明 |
|---|---|---|
| GPU 射线 | `gazebo_ros_gpu_laser`（`<sensor type="gpu_ray">`） | GPU 加速，高线数更流畅；输出 `LaserScan`/`PointCloud2` |
| Velodyne | `velodyne_simulator`（`velodyne_gazebo_plugins`） | 现成 VLP-16/32 模型，Noetic 可用 |

> 二者同样支持 `<noise type="gaussian">`，接口仍为 `/radar/points`。**首选仍是 Ray 插件**——依赖最少、配置最直白。

---

## 八、注意事项

1. **不用专用雷达插件**：`ainstein_radar_gazebo_plugins` 等第三方雷达插件仅发布 Kinetic/Melodic，Noetic 未发布、长期未更新，且输出为自定义雷达消息，需额外转换，不采用。
2. **不做动平台补偿**：仿真阶段雷达固定于世界原点，世界系与飞控 local ENU 重合（主文档第八章第 6 条），无需坐标变换。
3. **噪声类型固定高斯**：项目要求为高斯噪声，`<noise type="gaussian">` 即为标准实现，逐波束独立采样。
4. **参数不可外推真机**：所有 `eps`、`stddev` 等仅为仿真跑通，换真实毫米波雷达需重新标定（主文档第八章第 4 条）。
